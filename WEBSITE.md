# Website plan — `https://kimmo.cloud/php-20260924/`

Publish the PHP 2026-09-24 security-release tracker as a single-page
static site, generated by **Hugo** locally and rsync'd to a personal
nginx server (`haig`). The build infrastructure was seeded from
`~/src/cve-tracker-template` (`skeleton/` plus the `package/` overlay),
with the prose modelled on the live Unbound tracker (CVE-2026-81642) —
same distro scope, same publishing model; the table layout, the
lookup helpers, and the content differ.

## Architecture

- **Source repo:** `github.com/suominen/php-20260924` (this repo).
- **Generator:** Hugo ≥ 0.146.0 (standard edition). Run locally; nothing
  built in CI.
- **Source layout:** Hugo project under `site/`. The tracker is a single
  page at `site/content/_index.md`.
- **Theme:** PaperMod, integrated as a Hugo Module (no submodule). See
  `site/hugo.toml` and `site/go.mod`.
- **Dev environment:** Nix flake (`flake.nix`) provides everything the
  build, banner, publish, and lookup recipes call (Claude Code itself
  excepted). Auto-activates via `.envrc` with direnv.
- **Build:** `make build` → `hugo --minify --gc --cleanDestinationDir`,
  output in `site/public/`.
- **Publish:** `make dist` → `rsync -avz --delete site/public/`
  → `haig:/php-20260924/`, which the server's restricted rsync
  resolves to `~/.www/sites/kimmo.cloud/htdocs/php-20260924/`.
- **Web server:** existing nginx vhost on `kimmo.cloud` serves
  `htdocs/php-20260924/` directly at the URL path `/php-20260924/`.
  TLS, redirects, and certbot are managed by the host, not by this
  repo.
- **DNS:** unchanged. `kimmo.cloud` already resolves to the haig server.

## Naming

The tracker follows a release event, not a single CVE, so no CVE ID
names it: the slug is the upstream project plus the release date, and
it has no nickname. It is lowercase everywhere, so the repo, URL,
module path, systemd units, and banner share one spelling.

- repo: `~/src/php-20260924`, `github.com/suominen/php-20260924`
- Go module path: `github.com/suominen/php-20260924/site`
- URL: `https://kimmo.cloud/php-20260924/`
- systemd units: `php-20260924-tracker-update.{service,timer}`
- banner: `site/assets/php-20260924-tracker.svg` →
  `site/static/php-20260924-tracker.png`
- title: "PHP 2026-09-24 security releases — 11 CVEs across 8.2–8.5"

## Decisions

- **Hosting:** own nginx on `haig`, *not* GitHub Pages. Same as the
  sibling trackers.
- **URL / slug:** `https://kimmo.cloud/php-20260924/` — the release
  date, since the tracker covers a release with eleven CVEs rather than
  one headline bug.
- **Theme integration:** Hugo Modules. **Theme:** PaperMod.
- **Canonical source:** `site/content/_index.md`.
- **One table with a PHP column, not one table per branch.** PHP ships
  four supported branches with a fixed release each — the case
  `~/src/cve-tracker-template/DESIGN.md`'s *Parallel upstream tracks*
  rule answers with one identical-columns table per track. The user
  chose a single table instead, one row per (release, PHP branch)
  pair, with a *PHP* column for the upstream release each package
  builds and the branch's own threshold named in the Status note
  (`needs 8.4.26`). Rationale: what a reader most needs is "which PHP
  does my distribution run, and is it fixed?", and here the branch is
  a property of the distribution release (Debian ships one branch per
  release), so one table answers it in one place; four tables would
  scatter a single NixOS channel across four places. Cost, accepted:
  the fixed threshold varies row to row, so each vulnerable row names
  it, which the template's rule exists to avoid.
- **One verdict for all of a branch's advisories.** A row is Fixed
  when it closes every applicable advisory of its branch's release,
  Partial when only some; there is no column per advisory. The
  alternatives — a column per advisory (twelve columns) or keying on
  the highest-severity CVE alone — were rejected as unreadable and as
  letting a row read Fixed with holes open, respectively.
- **CVE-2026-17545 does not gate any row.** It affects PHP on Windows
  only and no tracked distribution builds for Windows; the user
  decided at seed that Fixed means every *other* advisory of the
  branch's release. It stays in the Advisories table, marked
  Windows-only.
- **GHSA-ch8v-r6jh-4vvr gates only 8.2 and 8.3 rows.** 8.4 and 8.5
  fixed it a release earlier, so a row at their 2026-09-24 release
  has it anyway, and the tracker's verdict follows the user's
  definition — the advisories of the *applicable* release.
- **The PHP release is read, not run.** Running `php --version` on a
  target system is not an option, and Debian's package versions don't
  show the PHP release reliably (`php-defaults` versions like `96`
  carry none at all), so `scripts/debian-versions` reads the branch
  from `php-defaults`' `PHP_DEFAULT_VERSION` and the release from each
  package's changelog, cross-checked against the version string. pkgsrc
  and nixpkgs keep all branches' versions in one file each, which the
  other two helpers read.
- **Dates are derived, not observed.** A *Fixed since* date comes from
  the source that shipped the fix — the Debian changelog or
  snapshot.debian.org, the pkgsrc `phpversion.mk` history, or, for
  NixOS, `scripts/nixos-first-shipped`.
- **Distro scope:** intentionally narrow, as in the sibling trackers —
  Debian sid / forky / 13 / 12; the NixOS channels (`nixos-unstable`,
  `nixos-unstable-small`, `nixos-26.05`, `nixos-26.05-small`),
  `nixpkgs-unstable`, and the ungated `master` and `release-26.05`
  branches; pkgsrc `pkgsrc-current` and `pkgsrc-2026Q3` — each with
  every PHP branch it ships. RHEL family, Amazon Linux, Ubuntu, Arch,
  Fedora, and Proxmox are out of scope.
- **Automated maintenance:** a user-level systemd timer
  (`systemd/php-20260924-tracker-update.timer`, twice daily at
  `06,18:05` — a slot no other tracker uses) runs `scripts/auto-update`
  with `scripts/auto-update-prompt.txt`, committing onto the
  `auto-update` branch only. Merges into `main` are manual.

## Risks & gotchas

- **Row count.** One row per release and PHP branch makes a long
  table (40 rows at seed, 28 of them NixOS/nixpkgs). Branch changes
  (a distribution adding 8.5 or dropping 8.2) add or freeze rows;
  `CLAUDE.md` § "When a distribution changes branch" has the rules.
- **Anchor drift.** The tracker links internally to
  `#distribution-status` and `#advisories`; don't rename those
  headings casually.
- **Subpath baseURL.** `baseURL = "https://kimmo.cloud/php-20260924/"`
  must include the trailing slash and the path component.
- **`.cleanDestinationDir`** wipes `site/public/` before each build.
- **rsync `--delete`** removes server-side files not present in the
  build output.
- **Client-side table tweaks.** `layouts/partials/extend_footer.html`
  rewrites the distribution table in the browser (group heading rows
  per distribution, status-cell tagging). With JavaScript disabled the
  table still renders correctly with the Distribution column visible.
  Rows sharing a distribution must stay contiguous.
- **JS-only sources.** The GitHub advisory pages, the NVD web pages,
  and the NixOS security tracker return nothing to WebFetch; the
  tracker reads the GitHub REST API and the CVE Services API instead.
- **Security-archive changelogs.** ftp-master's changelog metadata
  covers only the main archive; a `-security` upload's changelog is on
  tracker.debian.org, with `~` and `+` dropped from the version in the
  file name. `scripts/debian-versions` tries tracker.debian.org first.

## Social banner

The OpenGraph / social-preview image is generated from an SVG source:
`site/assets/php-20260924-tracker.svg` (1200×630) is rasterised to
`site/static/php-20260924-tracker.png` by `make banner`, which runs
`resvg`. The PNG is committed so ordinary `make build` / `make dist`
runs need no rasteriser.
